# ADR-001：使用本地 SQLite 与追加式证据

- 状态：已采纳
- 日期：2026-08-01

## 背景

现有材料体积小、需要离线使用，但来源口径冲突严重。用户需要长期更新，而不是一次性宽表。

## 决策

使用 Python 标准库和 SQLite；原始行不可覆盖，清洗值作为影子观测，官方核验和冲突作为追加记录。业务服务依赖仓储协议，不直接依赖 SQLite。

## 取舍

优点：零服务依赖、便于备份、事务完整、来源可追溯。缺点：多人高并发与复杂全文检索能力有限。若未来需要服务化，可实现新的仓储端口，而不修改领域规则。

## 被否决方案

- 单一CSV/XLSX：难以表达字段级来源、冲突和追加历史；
- 直接把旧`yes`清洗成布尔真值：会把缺少四科代码的历史声明冒充官方事实；
- 先上复杂概率模型：个人套卷和考生级数据不足，会产生伪精确结论。
